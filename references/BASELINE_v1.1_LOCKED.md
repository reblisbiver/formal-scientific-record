# Amendment A1 — Output language (2026-11-08; user-approved)

**Frozen additive requirement:** Every final Formal Scientific Record report must be in **English**, including headings, mathematical prose, tables, chart axes and legends, captions, validation labels, footnotes, and appendices. Original proper names, symbols, and citations are preserved as appropriate. **The conversation with the user continues in Chinese.**

This amendment affects presentation language only. It does not change the permitted scientific content, minimal-completeness objective, Information Promotion Rule, anti-inference restriction, provenance requirements, or scientific-compiler workflow. Subsequent changes to the frozen standard require prior explicit confirmation whether to *replace* or *amend/add*.

我现在认为，我们终于找到了一个比“设计报告模板”更准确的问题：

**如何让 AI 像研究者一样压缩科学信息，同时禁止它像研究者一样自由发挥？**

这两个要求并不矛盾，但不能仅靠 Prompt 实现。因为它们实际上涉及两种不同的能力：

- **信息选择**：从大量实验记录中，确定读者必须知道什么。
- **信息表达**：用尽可能少的定义、公式、表格和图形，无歧义地呈现这些信息。

前者决定报告有没有漏掉关键内容；后者决定报告是否精确、简洁、可读。

而我们此前的 Skill，基本只控制了第二件事中的排版，没有真正控制第一件事。

经过对你提供的 Note 和现有科研报告规范的比较，我倾向于一个新的方向：

> **不是让 Codex 编写科研报告，而是让它编译一份经过约束的科学事实表示。**
>
> 报告只能出现定义、已记录的研究问题、方法、条件、观测值、计算结果与验证状态。不能出现模型新提出的假设、科学解释或对结果意义的推断。

## 一、现有的成熟产物中，哪些值得借鉴？

我找到的几个体系都各自解决了部分问题，但没有一个能直接满足你的全部要求。

| 参考体系 | 真正值得借鉴的机制 | 不能直接照搬的地方 |
|---|---|---|
| 你提供的研究 Note | 从研究对象逐步建立数学关系，文字极度精简 | 依赖作者主动判断如何组织问题 |
| NeurIPS 论文正文与附录 | 正文只放理解实验必需的设置，完整超参与复现细节可放附录 | 正文仍包含作者的科学解释 |
| Registered Reports | 实验前的假设、方法、判定规则与实验后的结果分开 | 主要适用于预先明确假设的研究 |
| ML Reproducibility Checklist | 对模型、数据、评估和实验记录规定完备性要求 | 只保证信息齐全，不保证人类可读 |
| Quarto Manuscripts | 将正文与计算过程分离，自动生成公式、表格和图 | 解决的是出版流程，不决定什么值得呈现 |

这些判断分别参考了 [NeurIPS 官方报告规范](https://neurips.cc/public/guides/PaperChecklist)、[Registered Reports](https://www.nature.com/srep/journal-policies/registered-reports)、[机器学习复现清单](https://www.cs.mcgill.ca/~jpineau/ReproducibilityChecklist-v2.0.pdf) 和 [Quarto Manuscripts](https://quarto.org/docs/manuscripts/index.html)。

其中有一条非常重要的正式规范：NeurIPS 要求主要实验设置在正文中达到足以理解结果的程度，完整细节可以保存在附录或代码中。

**这正是我们一直没有处理好的问题：不是所有真实信息都应该获得相同的展示优先级。**

但更进一步，我认为还需要重新定义“最小完备”。

## 二、「最小完备」应该成为整个系统的核心原则

先区分两个概念：

**完整记录**：实验产生的事实都能被保存和查证。

**最小完备报告**：读者不查阅底层文件，也能无歧义地回答这份报告负责的科学问题。

它们不是同一个目标。

我建议用以下形式定义报告生成任务：

\[
R^*=\arg\min_{R\in\mathcal R}|R|
\]

满足：

\[
\operatorname{Coverage}(R,Q)=1
\]

\[
\operatorname{Faithfulness}(R,D)=1
\]

这里：

- \(D\)：经过核实的科学事实集合。
- \(Q\)：资料中已经明确的研究问题集合。
- \(R\)：生成的报告。
- Coverage：报告包含回答这些问题必需的信息，或者明确标出无法回答的部分。
- Faithfulness：报告中的事实与关系均可从原资料得到，不增加额外科学主张。
- \(|R|\)：报告的表达成本，不必简单等同于字数。

这只是我们设计系统时的**规范性目标**，不是我声称已经存在可直接计算的完美压缩算法。

真正的难点，是实现 Coverage。

## 三、我认为应该设计的最终产物

我现在不建议继续使用“实验定义—假设—结果—验证”作为所有报告的固定结构。

应该有一个更加通用的框架，但正文由不同的**科学陈述块**构成。

**SCIENTIFIC RECORD / CONCEPT — 阅读层示意**

### 一个科学问题，一组形式化关系

每个陈述块只承担一种职责。不要求所有类型在同一报告中出现。

**定义**
\[
R_t=s_{t,A_t},\quad A_t\in\{1,2\}
\]

**约束**
\[
\sum_{t=1}^{100}s_{t,a}=25,\quad a\in\{1,2\}
\]

**目标**
\[
S^*=\arg\max_{S\in\mathcal S}J(S)
\]

**测量**
\[
\Delta_m=m_{\mathrm{new}}-m_{\mathrm{base}}
\]

**结果**

对应的实测数值、对照表或分布图；仅在有数据时出现。

前三项来自你提供的 Note 的数学对象；测量项是通用实验表达示意。这里不是一份真实实验报告。

这套设计的特点是：**没有结论段，没有意义解释段，没有“下一步建议”，也不强制出现标题为“假设”的章节。**

如果研究中存在明确的原始假设，便展示假设及检验；没有就不生成。研究问题本身仍然需要展示，但不能伪造其预注册状态。

## 四、如何决定超参数、数据细节是否进入正文？

这是最难、也最值得解决的部分。

我建议建立一个**信息提升规则（Information Promotion Rule）**。

不是让 Codex 判断“什么比较重要”，而是检查每一项信息在当前报告中承担什么作用。

| 信息类别 | 正文展示条件 | 默认去向 |
|---|---|---|
| 研究对象、输入、目标输出 | 理解研究问题所必需 | 正文 |
| 本次改变的变量 | 决定比较对象 | 正文 |
| 数据范围、样本量、分析单位 | 决定结果的适用范围或数值口径 | 正文 |
| 评价指标及其定义 | 决定观测值代表什么 | 正文 |
| 实测结果、差值、误差范围 | 直接回答已记录的问题 | 正文 |
| 模型结构、关键超参数 | 影响方法定义或比较是否公平 | 正文或简表 |
| 其余超参数、环境、路径、日志 | 仅用于复现和审计 | 附录 / 底层文件 |
| 科学解释、扩展推断、新假设 | 不属于报告允许的内容 | **禁止生成** |

这里的关键是**相对性**。

例如 `learning rate`：

- 若实验比较不同学习率，它是自变量，必须出现在正文。
- 若实验比较 RAW3 与 FULL7，且学习率保持固定，它可以作为共同控制条件。
- 若实验只是分析选择分布，而学习率与该结果无关，则可能完全不需要在正文出现。

所以，同一个字段在不同实验中可以处于不同层级。

这是之前固定模板无法解决的。

## 五、怎样真正约束 Codex？

现在我认为不能再只依赖一个几十条规则的 Skill。

要把 Skill 设计成**带有确定性检验的编译流程**。

1. **提取科学事实**：定义、变量、方法、条件、指标、观测及原始研究问题。
2. **建立事实之间的关系**：输入 → 方法 → 观测；假设 → 指标 → 判定。
3. **选择最小完备子集**：只保留回答原始研究问题必需的科学对象。
4. **受限表达与排版**：公式、符号定义、参数对照、结果表、统计图。
5. **双重校验**：事实无新增、重要信息无遗漏、表达可进一步压缩吗？

其中最重要的是第三步和第五步。

### 第三步：不让 Codex 自由决定篇幅

例如可以规定：

- 一个研究问题对应一个独立的报告单元。
- 每项定义只出现一次，之后通过符号引用。
- 每个指标必须对应明确的测量对象和范围。
- 同一组数据不得既用表格重复完整展示，又用图形再次重复全部信息，除非两者承担不同的阅读功能。
- 未参与当前研究问题的超参数不能进入正文。

这些都是可以检查的结构或内容规则，比“请写得精简一点”有效。

### 第五步：引入删除测试

这可能是最接近人类作者反复精简文章的机制。

对报告中的每个陈述块 \(b\)，尝试删除：

\[
R'=R\setminus\{b\}
\]

然后检查：

\[
\operatorname{Coverage}(R',Q)
\]

如果仍然完整，而且不引入歧义，就说明该块在当前表达中可能是冗余的。

反过来，任何一项实验问题、关键定义或观测值没有对应展示，也要阻止报告通过验收。

当然，语义完整性无法靠简单程序百分之百证明。因此不能让同一个 Codex 随意宣称自己完成了压缩。我们需要让程序检查字段覆盖和关系约束，再通过独立检查测试语义上的遗漏。**这比多写几个 Prompt 更有可能稳定改善结果，但仍不等于能够自动达到专家精修的水平。**

## 六、我觉得还需要保留少量、但严格受限的自然语言

老师那份 Note 的精简不只是公式多，而是每句话都有明确的信息功能。

例如：

> The schedule is fixed before the participant begins and does not respond to their choices.

这句话很短，却同时确定了两个关键条件：预先固定、非响应式。

如果强行删除这类文字，报告可能反而变得不准确。

因此，我建议只允许四种自然语言功能：

1. 定义术语。
2. 指明适用条件与例外。
3. 陈述已经记录的实验操作和事实。
4. 标注数据缺失、校验失败或无法判定。

不允许“这说明……”“这一发现暗示……”“未来可以……”这样的模型推断性段落。

这样做不是禁止科学表达，而是**限制文本只能承担确定的语义功能**。

## 七、我的最终建议：先确定标准，不继续训 Codex

现在我们欠缺的其实不是一套排版规范，而是一个足够好的**目标产物标准**。

我建议将目标命名为：

**Formal Scientific Record（形式化科学记录）**

它与论文、Research Note、实验日志都不同：

| | 我们的目标 |
|---|---|
| 内容 | 已存在的科学事实及其明确关系 |
| 表达 | 数学化、紧凑、最小完备 |
| 组织 | 随研究问题变化，而不是固定章节 |
| 观测 | 精确数据、图表、估计及判定 |
| 推断与解释 | 禁止由模型新增 |
| 复现材料 | 完整保留，但不干扰阅读 |
| 最终介质 | 专业 LaTeX PDF，另存结构化数据 |

我建议先建立三份**人工制定的目标样例规范**，而不是立即让 Codex 从项目文件夹生成：

- **理论型**：以你提供的 Note 为标杆，考察定义、约束、方法与目标函数。
- **实验对照型**：考察变量、控制条件、指标、数值和检验。
- **分析型**：考察分布、时间序列、参数估计及其适用范围。

它们不需要同样的章节，但必须服从同一套表达语法和压缩规则。

然后，把 Skill 的任务从“写得像这三份样例”改成“生成的每个科学对象都必须符合类型规则、依赖关系和最小完备验收”。

**我目前最有把握的判断是：你需要的是一个 Scientific Compiler，而不是一个 Scientific Writer。** 它可以使用 Codex 来提取与规范化资料，但不能把最终正文交给 Codex 自由写作。

这轮没有修改 Skill。现阶段我也不会声称已有某个 Skill 能够可靠地自动实现教授级的精修质量。我们已经找到了几套可以组合的成熟规范，但最关键的“科学信息压缩与选择规则”仍需要专门设计和验证。
